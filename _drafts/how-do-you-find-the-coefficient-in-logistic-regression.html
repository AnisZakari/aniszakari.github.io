In this article, I assume you are already familiar with Linear Regressions.

When dealing with Linear Regression, you already know that we are looking for the linear combination of the features so that we minimize the differences between the predictions and the true labels. In other words, we are looking for the line that better fits the data points. What about logistic regression ? What do we minimize ?

If you want a fast answer, we minimize the Binary Cross Entropy with gradient descent. This may be a harsh answer if you are a newcomer in Data Science, so bare with me, we'll dive into details because there are some sophistications that are worth knowing. First let's get back to the general context of the logistic regression.

What is Logistic Regression ?

Like the Linear Regression, the Logistic Regression is a linear model that is looking for the best linear combination of the features so that we minimize the error between good predictions and the observations. Unlike Linear Regression we do not predict à continuous value like the salary or the weather but a category like Fake/Not Fake, Churn/Not Churn or Cat/Not Cat. We can summarize this by saying that we are predicting a True/False situation, we then talk about Classification. At the end of the day we want the output to be 0 or 1.

Let's take a quick example to describe the process:

Suppose that you run a business, you wonder if it is a good idea or not to launch a new product, so you want to estimate first the amount of users in your database that are likely to buy it. To simplify, you have access to the Salary and the Age of the users and you want to predict the probability of buying. Let say you sent an email to sell this new product to a representative sample of 1000 users.

Notice that we have two input columns and we only want one column containing zeros and ones as output. So we need some kind of projection that will map a two-dimensional space into a one-dimensional space. This can be done with linear combinations, in fact it is just a matrix multiplication.

First we build our design matrix X with the features Age and Salary. We then compute the linear combination of these two features, this will map the two columns (three in fact) into one. I didn't mention it before but note that we also include a column of ones because your line that better fits the data doesn't necessarily pass through the origin, so you need to include an intercept (if you need a mental representation of this, think of a 2 dimensional graph with Age on the X-axis that takes values from 18 to 80 and probability of buying on the Y-axis that takes values from 0 to 1). So far this is exactly the same process as Linear Regression. For now, Let's suppose that we already know the best values for the beta coefficients.

Now you end up with a column H containing different real values (they can take any value from -infinity to + infinity). How do you convert them to probabilities ?

Well there is a function named sigmoid that was specially designed for that use. For now we don't need to dive into technical details. I will simply show you what the sigmoid looks like.

It maps every real values into the interval [0,1]

To get the desired result, you basically just apply the sigmoid function to every value in the column. The new column gives us the probability of buying given the data X. This can be formally written as $latex P(Y=1 | X) &fg=000000&bg=ffffff&s=2$ .
Finally, you need to choose a threshold, we generally choose 0.5, which means that if the probability is above 0.5 you consider that the user is likely to buy, you labelize it as a 1 otherwise he is not and you labelize it as a 0.The threshold can be fine tuned depending on the case.

How do we fit the Logistic Regression to the Data ?

Allright ! That is cute but we still don't know how to choose the best beta coefficients...
For now we know how to compute probabilities given features. What is done in practice is that we first set the betas to random values and we iteratively vary them. With a special criterion we can check at each iteration if the model is getting better or not, that is to say if the predictions are matching the actual labels. This criterion is the binary cross-entropy, it is the equivalent of the Mean Squared Error of the linear regression. In fact, we don't really use the word "criterion" we use the word "loss" and we want to have a loss as little as possible because it quantifies how bad are the predictions. Lastly, to minimize the loss effectively, there is a mechanism that ensures you going in the right direction at each iteration, this mechanism is the gradient descent.

What is the Binary Cross-Entropy ?

I won't dive too deeply into the Binary Cross-Entropy as we need a dedicated article for that subject, which I'm planning to write. Let's provide a hint of what it is anyway.

Also, for clarity I didn't write $latex p_{i}(\beta) &fg=000000&bg=ffffff&s=2$ but keep in mind that they depend on the betas.

This is a very handy expression because when the true label is 1 then the second part of the expression cancels out. When the true label is 0 then the first part cancels out !

Another thing to notice is that there is a minus in this expression because the log of a value that lies between 0 and 1 is always negative so we add a minus to make the result positive because we want the error to be positive and big when the predicted values are wrong.

Also you can convince yourself that this expression measures an error because when the probability is very close to the correct label the loss or the error is very low. When the probability predicted is far from the true label, the loss tends to infinity. Bellow, you'll find an example:

Gradient descent

The Gradient descent aims at minimizing the loss function iteratively. At the end of the process you can find the global minimum if the function is convexe. Luckily this is the case with our loss function. At the end of the process you'll have the best possible betas given your Data, This topic also deserves its own article which I'm also planning to write.

After reading this article you might have several questions that come to your mind. I've listed some I can think of bellow.

Why Can't we use MSE (Mean Squared Error) as a loss for Logistic Regression ?

  • After having learnt the linear regression model, this might be very tempting to use the MSE as a loss fonction for the logistic regression. Unfortunately the MSE is not convex when applied to a Logistic regression, because all the sudden you have to deal with a sigmoid function inside the loss, you can easily find content on the internet that proves this claim . You always prefer to have convex functions when dealing with optimization problems because it ensures you to have a global minimum.
  • Another reason is that the binary cross-entropy penalizes more heavily bad predictions than the MSE. For instance, when the prediction is completely wrong:
    Mean_Squared Error( y_prediction = 0, y_true = 1) = (1-0)^2 = 1

    Binary_Cross-Entropy( y_prediction = 0, y_true = 1) = 1*log(0) = -infinity.

Wait a minute, why is Logistic Regression a linear model ?

Indeed the sigmoid function that maps the input features into 0 or 1 is not linear but what we mean by linear model is that there is a linear relationship between the features themselves. In other words, if we visualize X_age against X_Salary we will see a decision boundary that is a line.
